## 快速開始

1. `node db/seed.mjs` 建立 `db/school.db`
2. `node db/server.mjs` 啟動後端，開 `http://127.0.0.1:3001/`
3. 選擇身分頁籤（學生 / 老師 / 管理員），輸入帳號密碼登入（打 `POST /api/login`）
4. 登入頁有「⚡快速登入」按鈕，可一鍵切換展示帳號
5. 右上角「↺ 還原展示資料」可隨時重置回初始種子資料（`POST /api/db` 整庫覆寫）

## 核心規則

- **學期成績換算**：平時 × 30%＋期中 × 30%＋期末 × 40%，四捨五入取整數
- **GPA 對照**：90+ → 4.3；85+ → 4.0；80+ → 3.7；77+ → 3.3；73+ → 3.0；70+ → 2.7；67+ → 2.3；63+ → 2.0；60+ → 1.7；未滿 60 → 0
- **操行成績**：基點 85，嘉獎 +1、小功 +2.5、大功 +7.5、警告 −1、小過 −2.5、大過 −7.5，結果限制 0–100 分
- **請假流程**：學生送出（待審核）→ 導師通過 / 退回 → 通過時自動在出缺席產生當天各課「請假」紀錄（備註「請假申請通過」），已有同日同課紀錄則跳過不重複
- **課程排名**：同門課中有公布學期成績者才納入排序
- **選課限制**：學分上限 25、同時間課程跳出衝堂確認、額滿不可加選

## 資料模型

存於 `db/school.db` 的 SQLite 資料庫（後端 `db/server.mjs` 提供 `GET/POST /api/db` 整庫讀寫）：

- **users**：`{id, account, password, role(student/teacher/admin), name, dept, email, phone, birthday, address, advisorId(學生導師)}`
- **courses**：`{id, code, name, teacherId, credits, semester, time(例「週一 09:00-12:00」), room, capacity, desc}`
- **enrollments**：`{studentId, courseId}` 選課關係
- **grades**：`{studentId, courseId, regular(平時), midterm(期中), final(期末), score(學期成績)}`
- **attendance**：`{id, studentId, courseId, date, status(出席/遲到/缺席/請假), note}`
- **leaves**：`{id, studentId, date, reason, status(待審核/通過/退回), applyDate, reviewer, reviewNote}`
- **announcements**：`{id, title, content, authorId, authorName, date, pinned}`

## 常見操作

- **新增學生/老師**：管理員 → 帳號管理 →「新增帳號」，學生記得指派導師
- **開新課程**：管理員 → 課程總覽 →「新增課程」，時間格式請用「週X HH:MM-HH:MM」以便課表解析
- **登錄成績**：老師 → 授課課程 → 選課 →「學生成績」頁籤，填完三欄按儲存
- **審假**：老師 → 請假審核 → 通過 / 退回（通過自動寫入出缺席）
- **記獎懲**：老師 → 獎懲管理 → 選學生＋類別＋事由 → 登錄
- **資料亂了**：頂欄「↺ 還原展示資料」回到初始狀態

# PasswordVault 密碼管理器

WinUI 3 桌面密碼管理器：本地加密密碼庫 ＋ 瀏覽器自動填入 ＋ 桌面/遊戲 Auto-Type ＋ 剪貼簿降級。
所有資料只存本機（`%LOCALAPPDATA%\PasswordVault`），不經任何雲端伺服器。

## 功能

### 密碼庫（Vault.App，WinUI 3）
- 主密碼建立 / 解鎖（至少 12 字元），Argon2id 派生金鑰
- 新增 / 列表 / 鎖定，MVVM（CommunityToolkit.Mvvm）
- 閒置 5 分鐘自動鎖定，金鑰以 `CryptographicOperations.ZeroMemory` 清除
- 鎖定時同時清空剪貼簿

### 瀏覽器自動填入（Chrome / Edge，Manifest V3）
- `content.js` 偵測 `input[type=password]`（含 SPA / iframe），React 相容的填值方式
- 登入頁自動帶入、提交新帳密時嗅探儲存
- `popup` 一鍵填入；擴充功能本身碰不到資料庫，一律經 Native Messaging 問 Vault.App
- 網址比對用精確 host 相等（防 `googIe-login.com` 類釣魚），不是 `Contains`

### 桌面 / 遊戲 Auto-Type
- 全域快捷鍵 `Ctrl+Shift+L`：抓前景視窗標題＋行程名 → Regex 配對項目 → `SendInput` 逐字打出 `{USERNAME}{TAB}{PASSWORD}{ENTER}`
- 每項目可綁 `window_title_regex`（例 `(?i).*elden.*`），UI 有「3 秒後抓取視窗」幫你產生建議 Regex
- `SendKeys` 不用（對 DirectX / 全螢幕 / UAC 普遍無效），改用 `SendInput` Unicode 模式＋ 10–20ms 間隔
- 按住 Ctrl/Shift 時會等放開再打，避免修飾鍵污染輸出

### 剪貼簿降級（反作弊 / 打不進去時）
- `Ctrl+Shift+C`：只複製配對項目的密碼，不打字，回遊戲 `Ctrl+V`
- 複製後 App 自動最小化，方便切回遊戲
- 10 秒自動清除，且只清「還是我們那串文字」時才清（你中途複製別的東西不會被誤刪）
- 啟動/解鎖/複製時檢查 `ClipboardPolicy`：
  - `HKCU\...\Clipboard\EnableClipboardHistory == 1` → 警告 Win+V 會留痕
  - 跨裝置同步未被政策禁用 → 警告可能上雲，導引到 設定→系統→剪貼簿 關閉

## 架構

| 模組 | 位置 | 職責 |
|---|---|---|
| Vault.Core | `Vault.Core/` | 純邏輯：`Kdf`（Argon2id）、`Crypto`（AES-256-GCM）、`Locker`（記憶體金鑰＋自動鎖）、`VaultStore`（SQLCipher）、`AutoType`（序列解析＋標題配對） |
| Vault.App | `Vault.App/` | WinUI 3（`net10.0-windows10.0.22621`，WindowsAppSDK 2.5.1，Unpackaged）。`VaultService` 會話、`PipeServer`（NamedPipe `passwordvault-vault`，鎖當前使用者 SID）、`HotkeyService`、`AutoTyper`（SendInput）、`ClipboardService/Policy`、`ForegroundWindow` |
| Vault.NativeHost | `Vault.NativeHost/` | Console exe。Chrome 用 stdio 啟動，講 4-byte length-prefixed JSON（`ping / get-login / save-login`），轉發給 Vault.App 的 NamedPipe。自己不碰主密碼與金鑰 |
| BrowserExtension | `BrowserExtension/` | MV3：`manifest.json`、`background.js`（native 橋）、`content.js`（找表單＋填值＋嗅探）、`popup.html/js`、`com.passwordvault.host.json`＋`install-host.ps1`（寫 Chrome/Edge registry） |

### 安全設計
- KDF：Argon2id（m=64MB，t=3，p=4）→ 32 byte 金鑰；salt 16 byte 存側車檔（非機密）
- 驗證：只存 `SHA256(key)` 當 verifier，不存主密碼；解密時 `FixedTimeEquals` 比對
- 欄位級：AES-256-GCM，blob = nonce(12)＋cipher＋tag(16)；檔級：SQLCipher `PRAGMA key` 整檔加密
- 金鑰只在解鎖期間放記憶體（`Locker`），鎖定/`Dispose` 即 `ZeroMemory`；`SecureString` 已棄用故不用
- Regex 配對一律 200ms 超時，無效 pattern 永遠不命中、不拋錯
- `url_hash`（SHA256 正規化網址）是唯一明碼索引，只做快速比對

### 資料表（SQLCipher）
- `vault_meta(id=1, salt, verifier)`
- `items(id, folder_id, name_enc, url_hash, url_enc, username_enc, password_enc, totp_enc, notes_enc, window_title_regex, autotype_seq DEFAULT '{USERNAME}{TAB}{PASSWORD}{ENTER}', revision, created_utc, updated_utc)`
- `history(item_id, revision, snapshot_enc)`

## 使用流程

### 桌面 App
1. 開 `Vault.App\bin\x64\Debug\net10.0-windows10.0.22621.0\Vault.App.exe`
2. 主密碼（≥12 字元）→ 建立新密碼庫 → 新增項目
3. 選項目 →「3 秒後抓取視窗」→ 切到遊戲 → 回來按「綁定」→ 切到遊戲按 `Ctrl+Shift+L`

### 瀏覽器接線（ID 拿到才能綁 allowlist）
1. `chrome://extensions` 開開發者模式 → 載入未封裝 `BrowserExtension/` → 抄下 ID
2. `dotnet build Vault.NativeHost -c Release`，再跑 `.\BrowserExtension\install-host.ps1 -ExtensionId <ID>`
3. 跑 `Vault.App.exe` 並解鎖 → 開登入頁點擴充 popup 填入

## 已知限制
- 子網域要完全相等才命中瀏覽器填入（`a.example.com` ≠ `example.com`）
- 存新帳密目前直接寫入，無確認 UI
- 有反作弊（Vanguard / EAC）、管理員視窗（UAC）時 Auto-Type 可能無效 → 用剪貼簿降級，不要硬繞（會被當外掛）
- 剪貼簿明文期間同使用者行程都讀得到；Win+V 歷史 / 雲端同步開著會留痕（App 會警告，建議關閉）
- `Microsoft.Data.Sqlite` 傳遞依賴 `e_sqlite3 2.1.11` 有 `NU1903` 弱點通告，不擋編譯，等上游修再升版

## 2. Docker 學習記錄

### 2.1 Docker 是什麼？為什麼要用？

- **映像（Image）**：唯讀模板，如 `nginx:1.27-alpine`。`Dockerfile` 就是食譜。
- **容器（Container）**：映像的執行個體，彼此隔離但共享宿主核心，比 VM 輕量。
- **倉庫（Registry）**：如 Docker Hub，`docker pull` 即下載。
- 本作業體會：以前要在本機裝 Node＋Python＋Rust＋Postgres＋Nginx 五種環境，版本衝突惡夢；
  用 Docker 後每個服務各自獨立，`docker compose up` 一鍵全起，換電腦也能重現。

### 2.2 學會的 Dockerfile 指令（本專案實際用到）

| 指令 | 作用 | 本專案範例 |
|---|---|---|
| `FROM` | 基底映像 | `FROM node:20-alpine`（輕量 Alpine 省 ~80% 體積） |
| `WORKDIR` | 工作目錄（自動 mkdir＋cd） | `WORKDIR /app` |
| `COPY` | 複製檔案進映像 | `COPY server.js ./` |
| `RUN` | 建置期執行（會留層） | `RUN npm install --omit=dev` / `RUN pip install -r requirements.txt` / `RUN cargo build --release` |
| `EXPOSE` | 聲明監聽埠（文件性質，真正映射靠 compose `ports`） | `EXPOSE 3001` |
| `CMD` | 容器啟動預設命令 | `CMD ["node","server.js"]` |
| `COPY --from=builder` | 多階段建置，只拿產物 | Rust：編譯階段 `rust:bookworm` → 執行階段 `debian-slim`，映像從 ~1GB 縮到 ~80MB |

> **層快取（Layer Cache）心得**：把不常變的先 COPY（`package.json` / `requirements.txt` / `Cargo.toml`），
> 再 `RUN install`，最後才 COPY 原始碼。這樣改一行 code 不會重裝依賴，build 快很多。

### 2.3 學會的 docker-compose.yml 觀念

- **services**：定義 6 個容器，`container_name` 方便 `docker logs micro-node` 除錯。
- **build vs image**：自建服務用 `build: ./backend-node`；直接用官方的用 `image: postgres:16-alpine`。
- **ports vs expose**：`ports: "8080:80"` 打洞到宿主（只有 nginx 需要）；`expose` 僅容器間可見，更安全。
- **environment**：注入 `DATABASE_URL`，讓 Node/Python 用 `postgres` 這個 DNS 名連 DB（不是 localhost！這是新手最常踩的坑）。
- **depends_on + healthcheck**：`postgres` 設 `pg_isready` 健康檢查，Node/Python 等 DB ready 才啟動，避免連線被拒。
- **volumes**：`pgdata:/var/lib/postgresql/data` 讓 DB 資料 survives `docker compose down`；`./db/init.sql:/docker-entrypoint-initdb.d/...:ro` 首次啟動自動建表。
- **networks**：自建 `micronet` bridge，同網段容器可用 service name 互連（`http://api-python:5000`）。

### 2.4 學會的常用指令

```bash
docker compose up --build -d   # 建置＋背景啟動全部
docker compose ps              # 看服務狀態
docker compose logs -f         # 追 log（可加服務名，如 -f api-node）
docker compose down            # 停止並刪容器（volume 保留）
docker compose down -v         # 連 volume 一起刪（DB 資料清空，慎用）
docker exec -it micro-postgres psql -U app -d appdb  # 進 DB 下 SQL
docker images / docker ps      # 看映像 / 執行中容器
```

### 2.5 Nginx 反向代理心得

- 瀏覽器只打 `:8080`，nginx 依路徑前綴分流（`location /api/node/` 等），後端可隨意增減、換語言，前端無感。
- `rewrite ^/api/node/(.*)$ /$1 break;` 把前綴剝掉，後端只需寫乾淨的 `/`、`/health`、`/db`。
- `proxy_set_header Host / X-Real-IP` 保留原始請求資訊。
- `upstream` 區塊讓 compose DNS 負載均衡未來可擴展（`docker compose up --scale api-node=3`）。

## 5. 遇到的坑與解法（供老師／同學參考）

| 坑 | 解法 |
|---|---|
| 後端連不到 DB（`localhost:5432 refused`） | 容器內 `localhost` 是自己，必須用 service name `postgres:5432`，靠 `DATABASE_URL` 注入 |
| Node 比 DB 先啟動導致 crash | `depends_on: condition: service_healthy`＋`pg_isready` healthcheck |
| `/api/node` 404 | nginx `location` 需處理無尾斜線，另加 `location = /api/node { return 301 /api/node/; }` |
| Rust 映像 1GB 太大 | 改多階段建置，執行期只用 `debian:bookworm-slim`＋二進位檔 |
| Windows 換行 `^M` 導致 sh 失敗 | 全用 JSON 陣列 `CMD`，避開 shell；存檔用 LF |
| Port 被佔用（5432/8080） | `docker ps` 查兇手，或改 compose `ports` 左側 |

# Blog — 現代軟體工程測試示範專案

一個完整的部落格應用，專門示範**三種層級的軟體測試**：

| 測試層級 | 測試對象 | 技術 | 位置 |
|---------|---------|------|------|
| 1. 單元測試 (Unit Test) | Rust Server（必測） | `cargo test` | `server/src/db.rs` 內嵌測試 |
| 2. 系統測試 (System Test) | Web API（整個服務） | Rust + `reqwest` 打真實 HTTP | `server/tests/system_api.rs` |
| 3. E2E 測試 (End-to-End) | 完整網頁（無頭瀏覽器） | Playwright + Chromium Headless | `e2e/tests/blog.spec.js` |

> **測試金字塔示意**
>
> ```
>        ／ E2E (4 個) ＼          ← 最少，最慢，最接近真實使用者
>      ／ 系統測試 (8 個) ＼       ← 中等，驗證 API 合約
>    ／ 單元測試 (9 個) ＼         ← 最多，最快，驗證最小單位
> ```

---

## 一、專案架構

```
blog/
├── server/                 # Rust 後端（axum + SQLite）
│   ├── src/
│   │   ├── main.rs         # 進入點：啟動 HTTP 伺服器 (port 8080)
│   │   ├── lib.rs          # 讓測試可以 import 內部模組
│   │   ├── api.rs          # HTTP 路由與 handler（/api/posts CRUD）
│   │   ├── db.rs           # PostRepo：SQLite 資料存取 ← 單元測試就在這裡
│   │   └── models.rs       # 資料模型 (Post / NewPost)
│   └── tests/
│       └── system_api.rs   # 系統測試：透過真實 HTTP 測 Web API
├── client/                 # Node.js 前端（原生 HTML/JS，不需測試）
│   ├── server.js           # 極簡 Node 靜態檔伺服器 (port 3000)
│   └── public/
│       ├── index.html      # 部落格頁面（含 data-testid 供 E2E 定位）
│       ├── app.js          # 呼叫 API、渲染文章列表
│       └── style.css
├── e2e/                    # Playwright E2E 測試（無頭瀏覽器）
│   ├── playwright.config.js
│   └── tests/blog.spec.js
└── README.md               # 本檔案
```

### 技術選型理由

- **Server 用 Rust（一定要測）**：Rust 生態系有內建的測試框架（內建 `#[test]` 屬性＋`cargo test`），零額外依賴；且系統程式語言的邏輯錯誤後果嚴重，因此後端是測試重點。
- **Client 用 Node.js（可不測）**：前端只是簡單的靜態頁面（原生 HTML/JS），商業邏輯極少，依照「server 一定要測、client 可以不測」的原則，把測試資源集中在後端。
- **SQLite**：單檔資料庫，測試時可輕鬆建立 in-memory 資料庫，讓單元測試之間完全隔離。

### Web API 規格（系統測試的標的）

| Method | Path | 說明 | 成功狀態碼 |
|--------|------|------|-----------|
| GET | `/api/health` | 健康檢查 | 200 |
| GET | `/api/posts` | 文章列表（新→舊） | 200 |
| POST | `/api/posts` | 建立文章 | 201 |
| GET | `/api/posts/{id}` | 取得單篇 | 200 / 404 |
| PUT | `/api/posts/{id}` | 更新文章 | 200 / 404 |
| DELETE | `/api/posts/{id}` | 刪除文章 | 200 |

建立文章的請求主體：`{ "title": "標題", "body": "內容", "author": "作者" }`（缺少 `title` 會回 `422`）。

## 二、三種測試的詳細說明

### 1. 單元測試 — Rust Server

**測什麼**：最小可測單位。`PostRepo` 的每個 CRUD 方法在 in-memory SQLite 上逐一驗證，不經過 HTTP、不經過 axum，非常快。

**如何測**：Rust 內建測試框架，直接在原始碼同檔案寫 `#[cfg(test)] mod tests`，用 `cargo test` 執行。

**測試案例**（`server/src/db.rs` 底部）：

| 測試 | 驗證點 |
|------|--------|
| `create_and_get_post` | 建立後能取回相同內容 |
| `create_sequential_ids` | id 遞增 |
| `list_posts_returns_newest_first` | 列表排序為新→舊 |
| `update_post_changes_fields` | 更新改變欄位、保留 created_at |
| `update_missing_post_fails` | 更新不存在的文章要失敗 |
| `delete_post_works` | 刪除一次成功、重複刪除回 false |
| `tables_start_empty` | 新資料庫是空的 |

**執行方式**：

```powershell
cd blog/server
cargo test
```

### 2. 系統測試 — Web API 測試

**測什麼**：把整個 axum 伺服器**真的跑起來**（綁隨機 port、用暫存 SQLite 檔），用 `reqwest` HTTP client 打真的網路請求，驗證：

- HTTP **狀態碼**是否正確（200/201/404/400/422）
- 回應 **JSON 格式**與欄位內容
- 完整的 **CRUD 業務流程**（建立→查詢→更新→列表→刪除→查詢變 404）
- **錯誤處理**（查無此文章 404；缺必填欄位 422；id 不是數字 400）

這一層已經包含 HTTP 框架、序列化、路由，但**不包含瀏覽器**，所以比 E2E 快、比單元測試更接近真實系統行為。每個測試都啟動自己獨立的伺服器＋暫存資料庫，互不干擾。

**執行方式**（也可單獨跑這組整合測試）：

```powershell
cd blog/server
cargo test --test system_api
```

**測試案例**（`server/tests/system_api.rs`）：

| 測試 | 驗證點 |
|------|--------|
| `test_01_health_check` | GET /api/health → 200 + `{"status":"ok"}` |
| `test_02_empty_list_returns_empty_array` | 空資料庫列表回 `[]` |
| `test_03_create_post_returns_201_and_post` | POST → 201 與完整欄位 |
| `test_04_full_crud_flow` | 完整 CRUD 流程含 404 |
| `test_05_get_missing_post_returns_404` | 查不存在的文章 → 404 |
| `test_06_create_without_title_fails` | 缺 title → 422 |
| `test_07_invalid_id_returns_400` | id 非數字 → 400 |
| `test_08_delete_missing_post_creates_deleted_false` | 刪不存在 → `{"deleted":false}` |

### 3. E2E 測試 — Playwright 無頭瀏覽器

**測什麼**：從「使用者」的角度測試整個系統：真的開一個（無頭 = headless，不顯示視窗的）Chromium 瀏覽器，載入 `http://localhost:3000`，模擬使用者填表單、按下按鈕、看畫面上有沒有出現預期的內容。

**特點**：

- `playwright.config.js` 會**自動啟動**兩個伺服器（Rust API + Node 前端），測完自動關閉（`webServer` 設定；若服務已在跑則會重用）
- 使用 `data-testid` 屬性定位元素，不受改版動畫/文字影響
- 失敗時自動截圖（`screenshot: "only-on-failure"`）＋保存測試軌跡（trace）

**測試案例**（`e2e/tests/blog.spec.js`）：

| 測試 | 模擬的使用者故事 |
|------|----------------|
| 首頁正確載入 | 開啟首頁，看得到標題和發文表單 |
| 發表新文章會出現在列表 | 填寫表單→點「發表」→新文章出現在頁面上 |
| 標題沒填時表單不能送出 | 只填內容不填標題，瀏覽器擋下送出（HTML required） |
| 建立的文章重新載入後仍存在 | 發表→重新整理→文章仍在（驗證資料真的存進資料庫） |

**執行方式**：

```powershell
cd blog/e2e

npm install
npx playwright install chromium

# 執行測試（自動帶起 API 與前端伺服器）
npx playwright test

# 想看瀏覽器視窗執行過程（有頭模式）
npx playwright test --headed

# 查看測試報告
npx playwright show report
```

## ✨ 功能介紹

### 顧客端（點餐頁）
- 菜單依分類（主食、湯品、飲料...）排版顯示
- 每道菜可加減數量，即時更新購物車總價
- 送單時填寫**姓名**、**桌號/取餐號碼**、**備註**（少辣、加蛋...）
- 送出後顯示**訂單編號**與**總金額**
- 售完菜品自動變灰、無法點選

### 店家端（廚房管理頁）
- 即時檢視所有訂單，每 **10 秒**自動刷新
- 依訂單狀態以顏色標示：🟠 處理中 / 🟢 已完成
- 可一鍵標記完成、重新開啟、刪除訂單
- 可切換是否顯示已完成訂單

### 後端 API
| 方法 | 路徑 | 用途 |
|------|------|------|
| GET | `/api/menu` | 查看菜單 |
| POST | `/api/menu` | 新增菜品 |
| POST | `/api/orders` | 送出訂單 |
| GET | `/api/orders` | 查看訂單（可用 `?status=pending` 過濾） |
| PATCH | `/api/orders/:id` | 更新訂單狀態 |
| DELETE | `/api/orders/:id` | 刪除訂單 |

> 安全性設計：訂單總價由後端依資料庫價格重新計算，而非信任前端資料，防止金額竄改。

## 🏗️ 架構與技術

```
用戶 (瀏覽器 / 手機)
        │
        ▼
Cloudflare Workers (Hono) ──── 靜態頁面 (public/)
        │
        ▼
Cloudflare D1 (SQLite)
  ├─ menu_items       菜單
  ├─ orders           訂單主表
  └─ order_items_placed  訂單明細
```

- **Cloudflare Workers**：全球邊緣節點運算，無伺服器、自動擴展
- **Hono**：專為 Workers 設計的輕量 web 框架
- **Cloudflare D1**：邊緣 SQLite 資料庫，免費額度即可運行
- **純原生前端**：HTML + CSS + Vanilla JS，無需 build step

## 🚀 快速開始

### 本機開發
```bash
npm run dev      # 啟動本機 dev server (http://localhost:8787)
```

首次在本機跑之前，先初始化本機資料庫：
```bash
npx wrangler d1 execute food-ordering-db --local --file=./schema.sql
npx wrangler d1 execute food-ordering-db --local --file=./seed.sql
```

### 部署到 Cloudflare
```bash
npx wrangler login          # 第一次需要登入（瀏覽器授權）
npm run deploy              # 套用 schema/seed 到雲端 + 部署 Worker
```

> ⚠️ 注意：`deploy` 腳本會重跑 `seed.sql`，多次部署會累積重複菜品。
> 若要修改菜單，建議直接對資料庫操作：
> ```bash
> npx wrangler d1 execute food-ordering-db --remote --command "UPDATE menu_items SET price=60 WHERE id=1"
> ```
