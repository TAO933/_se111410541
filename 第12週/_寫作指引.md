# 寫作指引（內部模板，不屬於書稿正文）

本檔是全書一致性基準。所有章節作者都必須遵循。

## 書籍基本資料

- **書名**：《從 LLM API 到自主 Agent：現代 AI 系統架構與工程實戰》
- **定位**：工程實戰向，主打「無框架優先」——前 6 章只用官方 SDK 手刻，第 10 章才引入框架。
- **語言**：繁體中文，台灣技術用語（程式碼、串流、預設、微調、剖析、記憶體、阻斷）。
- **讀者**：有 Python 或 TypeScript 基礎、想真正理解 Agent 底層的工程師。

## 每章固定結構（四段式節奏＋頭尾）

1. **章首**
   - `# 第 N 章：標題`
   - 一段 80–120 字的「本章導讀」
   - `> 本章你將學到` 3–5 條列點
   - 一張 Mermaid「本章地圖」流程圖（可選，但鼓勵）
2. **問題場景**（約 600–900 字）
   - 用一個具體、可共情的真實痛點開場（例如「上線三天後，客服機器人開始把退款規則寫成詩」）。
   - 清楚指出「直覺解法為什麼不夠」。
3. **核心設計模式**（約 1200–1800 字）
   - 拆解原理，不要只列名詞。
   - 至少 1 張 Mermaid 圖（流程圖／時序圖／架構圖擇一或並用）。
   - 可用表格比較方案。
4. **原生程式碼實作**（約 1000–1500 字＋完整程式碼）
   - Python 3.11+ 優先，含型別標註，用 `python-dotenv` 讀取 API key。
   - 每個程式碼區塊前標明檔名，例如 `agent/loop.py`。
   - 程式碼要能真的讀懂、最好能直接執行；不要虛構不存在的 SDK 方法。
   - 版本敏感處加註，例如 `> 以 openai-python v1.x 為例`。
   - 需要 TypeScript／協定定義時可穿插，但主線維持 Python。
5. **生產環境踩坑指南**（約 600–900 字）
   - 至少 4 條，每條格式：`### 坑 N：標題` + 症狀／原因／解法。
   - 尽量用表格或條列，易於掃讀。
6. **章末**
   - `## 小結`（3–6 條）
   - `## 練習題`（3 題，由淺入深）
   - `## 延伸閱讀`（真實文件或論文連結，2–4 筆）

## 篇幅

- 每章目標 4–8 頁（約 3500–5500 字加上程式碼與圖）。
- 不要灌水；每個段落都要推進讀者理解。

## 程式碼規範

- 使用 `from dotenv import load_dotenv; load_dotenv()` 與 `os.environ["OPENAI_API_KEY"]`。
- 同步與非同步都出現時，明確標註何時用 `asyncio`。
- 錯誤處理要寫出來（try/except、重試、逾時），不要只寫快樂路徑。
- 避免在程式碼裡放真實金鑰。

## Mermaid 規範

- 一律使用 ```mermaid fenced code block。
- 節點標籤用中文並以引號包住，例如 `A["觀察 Observe"]`。
- 每章至少 2 張圖；其中至少 1 張是 `sequenceDiagram` 或 `flowchart`。
- 圖要簡單可讀；太複雜就拆成兩張。
- 可用的圖類型：`flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`classDiagram`、`erDiagram`。
